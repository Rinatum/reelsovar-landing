# Инструменты для проверки движения и производительности

Проверено по официальным репозиториям GitHub 2026-11-05. Запрос владельца: найти frontend optimization / QA инструменты, способные помочь с рывками, замершими превью и стартовыми провалами.

## Подходящие проекты

- Chrome DevTools MCP: https://github.com/ChromeDevTools/chrome-devtools-mcp . Официальный MCP Chrome DevTools, в том числе запись и анализ performance trace, сеть, screenshots. В репозитории есть skills/chrome-devtools/SKILL.md. Подходит для локализации длинных задач, стоимости рендера и задержек загрузки. Документация подключений к уже работающему браузеру: docs/advanced-usage.md.
- Playwright MCP: https://github.com/microsoft/playwright-mcp . Браузерные сценарии и воспроизводимая автоматизация. Уже установлен на pet; в этой задаче используется существующий playwright-core через CDP общего Chrome. Важно: структурированный снимок accessibility tree сам по себе не показывает, меняется ли видеоизображение. Поэтому нужны реальные screenshots и измерения кадров.
- Lighthouse CI: https://github.com/GoogleChrome/lighthouse-ci . Проверки загрузки и performance budget на изменениях. Полезное дополнение, но его оценки не заменяют проверку движения конкретных видео в середине страницы. User flows: https://github.com/GoogleChrome/lighthouse/blob/main/docs/user-flows.md .

## Что применено без установки новых пакетов

Те же базовые возможности существующего Chrome DevTools Protocol и Playwright. Новые MCP/пакеты не устанавливались, новый браузер не запускался. Автоматические загрузки тестовых данных во внешние сервисы не нужны.

Новый сценарий qa/rendered-video.mjs проходит все 12 примеров, три клипа hero и все три тройки результатов в блоке «Контент на неделю». Для каждого видимого видео сохраняет currentTime, totalVideoFrames, droppedVideoFrames, paused/ready и две реальные картинки браузера с интервалом. qa/rendered-pixels.py сравнивает внутренние области карточек на этих screenshots — это проверяет фактически показанное изображение, а не только успешный play().

Отдельные сценарии проверяют задержку загрузки результатов, поведение общего исходника во время ожидания, отсутствие показа неподвижных результатов до готовности всех трёх потоков, мобильную компоновку, reduced motion, паузу, полный просмотр со звуком и отсутствие ошибок сети.

Предел проверки: Chromium на pet. Физический Firefox Mac владельца этим не заменяется. Обещание «плагин автоматически найдёт все лаги во всех браузерах» было бы некорректно. Проверяемый критерий этой правки — каждый реально видимый ролик меняет кадры, а не только имеет флаг paused=false.
